- 2026-08-25 - #17 Branch-protection setup now sends its payload as a BOM-free temp file instead of piping it into gh (PR #44). Cause measured on PowerShell 5.1.26100.9168: a string piped into a native process carries a UTF-8 byte-order-mark whenever the caller's session set $OutputEncoding to the BOM-emitting UTF-8 encoding (received bytes efbbbf7b2261 against 7b2261 from a default shell), and GitHub's JSON parser rejects it with Problems parsing JSON (HTTP 400), which is why it reproduced on one machine and not another. Write-PayloadFile is now the file's single payload-write site, writing UTF8Encoding($false), anchoring a relative path against (Get-Location).ProviderPath, and reporting a write failure with a named message and non-zero exit; -EmitPayload gained -PayloadPath, writing through that same function so the offline seam tests the bytes the PUT sends, with both empty-path cases made errors rather than silent fall-through to a live PUT. Rejected design, also measured: setting $OutputEncoding inside the script keeps the pipe in one line, but the script-scoped form silently corrupts a non-ASCII character to ? and only the global form is correct, mutating state outside the script.
