# What it checks

Each line: what a check catches, then what it misses. CI runs the `npm` scripts below except `check:evidence` and `check:served`.

- `npm test`: a failing test, including one that fails when a path from the old tree comes back or a kept tool cites a deleted file. Misses code no test covers.
- `lint`: ESLint findings in JavaScript. Misses PowerShell and prose.
- `format:check`: Prettier drift. Misses PowerShell.
- `check:budget`: the shared markdown over 20,000 tokens, or a reviewer's reading over 6,000. Its guard fails a PR that loosens a cap or the counting (a new `notCounted` entry in `repo-profile.json`, or in `governance-manifest.json` in the parent only), unless that is its only change. Misses the owner's yes (honored, not enforced), script or CI-step edits, and pushes (no guard).
- `check:banned`: banned phrases in the tree, vendored skills and buildlog; filler words in the tree. Skips the upstream files copied into `.claude/skills/impeccable/` (`SKILL.md`, `reference/`, `scripts/`), not our `NOTICE.md`. Misses other files and commit text.
- `check:emdash`: an em dash on a line a PR adds (locally, uncommitted work too), except in the same upstream files of `.claude/skills/impeccable/`. Skips the committed range when a commit says `This reverts commit <sha>`, which an agent can type. Misses commit and PR text, plain pushes.
- `check:seats`: a bad `seats.json`; a seat's agent, skill or a profile lens that names no file in `.claude/`; a model ID in shared markdown; on a PR, whether it qualifies for the configuration lane (only seat values, or only user-started skill files) and the path that keeps it out. Misses the owner's yes, as above.
- `seat-drill` (in `npm test`): a test that reads the root `seats.json` other than through `tests/shipped-seats.js`, a script `main()` call that would fall back to it without `--seats`, or a test that fails once every shipped model moves to another family. Misses a root read built from a variable, a `main()` call not written as `main({ argv: [...] })`, a CLI spawn without `--seats`, and a test that pins a model without the helper.
- `check:design`: a design record over 150 words, missing its date and issue line, `Decided:`, `Why:` or `Gave up:`, out of date order, or under a changed header; notes records over 100 words. Misses whether a record is true or worth keeping.
- `check:evidence`: a PASS whose working-tree id differs, or whose cited lines do not exist. Misses the review's judgment.
- `check:served` (step 12): a subagent served off its seat's model or effort.
- `commit-msg`: a commit staging a non-`.md` file with no issue named (`(#N)`, closing keyword, `issue-N` branch). Misses whether the issue was reviewed. Prints a notes reminder on every commit, never blocking. Local; `--no-verify` skips it.
- `pre-commit`: a child staging a shared path outside a sync branch. `--no-verify` skips it; CI does not back it.
- `before-issue-create`: `gh issue create` lacking the `needs-issue-review` label or a body file, or carrying `owner-approved` or a body opening with `Owner-approved:`; an add of `owner-approved` unless the whole command is `gh issue edit <N> -R owner/name --add-label owner-approved`, the owner's last typed message is an approve, and the hand-off it answers ends `Approve?` with a `#<N> Title:` line, once per issue per yes, never from a subagent; a shell command naming a chat log by a path written out in full. Shows the owner the `Approved:` or `Not approved:` line itself. Misses a label held in a variable, a chat log edited with the Write tool or reached by a built path, a deleted `.run_state/approvals.log`, a tag that then fails to land (the line already showed), and tools other than Bash and PowerShell.
- `spawn-check`: an `Agent` call with no role tag, a model or effort off its seat, a reviewer in the background; where `before-issue-create.ps1` is wired, an `issue-reviewer` spawn that names no single issue (`#N` or `owner/name#N`), names one without `owner-approved`, or whose lookup fails or takes over 5 seconds. Misses `claude -p` and remote sessions; allows if `seats.json` is unreadable. The tag and the `#N` are the agent's word.
- `edit-gate`: until the owner types `/build`, `/buildlog`, `/rca`, `/realign` or `/resume` in the session, an Edit, Write or NotebookEdit outside scratch, memory and plans, and a Bash or PowerShell command not on its read-only list. Sees only those five tools, so an MCP tool that runs code is unchecked. Misses a listed command that writes in a way the list did not foresee. Children get the file but not the wiring, since `.claude/settings.json` does not sync.
- `unlock-edits`: writes the session's unlock marker when one of those five is typed. The model's own Skill call never fires it.
- `session-greeting`: sets `core.hooksPath` and says if both git hooks are armed; warns on an effort override, a low `maxEffortLevel`, a leftover `.run_state/hard`, or `CLAUDE_CODE_FORK_SUBAGENT` not `0` (fork mode). Cannot see whether the Agent tool then offers `run_in_background`.
- `goal-check`, `after-edit`, `before-reply`, `reviewer-done`: add a note, never block. Nothing checks they were acted on. Children get `before-reply` but not the wiring, since `.claude/settings.json` does not sync.
- `issue-guard.yml`: labels `unverified-issue` on an issue opened without `needs-issue-review`; never blocks. Applies where `.github/workflows/issue-guard.yml` exists, since `.github/**` is not shared.
- Dependabot auto-merge: merges a Dependabot PR on green `build`. Misses whether the bump is safe.
