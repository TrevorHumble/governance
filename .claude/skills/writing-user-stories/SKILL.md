# Writing a user story

One sentence: As a <who>, I want <what I can do>, so that <why it matters to me>.

- **Who** is a person or an agent who uses the result, never "a developer" because the work is technical. For a governance change, it is the agent or the owner running the process.
- **What** is something they can do, not a piece you will build. "Save a recipe from a web page" is a feature; "add a recipes table" is a layer.
- **Why** is the intent. The criteria serve it, so a later reader who meets a case no criterion names can decide from the why.

Use the owner's words and add no goals they did not state. If the vision is vague ("make it feel faster"), pick the one smallest thing someone could do or notice, and put it to the owner at the hand-off as a question. Do not invent a program with targets.
